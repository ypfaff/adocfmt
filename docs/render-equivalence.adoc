= Render equivalence

Formatting is correct when it does not change what the reader of the rendered document sees.
Asciidoctor is the reference implementation: it defines what a document means.
The checks render the input and the formatter's output, then compare the two.

== The three checks

Rendering::
Both HTML renderings, with every run of whitespace collapsed to a single space.
Where a paragraph wraps is invisible in the rendered page, because HTML shows any run of whitespace as one space.
Comparing the renderings byte for byte would therefore report line breaks no reader can see.

Comments::
The comment lines of both AsciiDoc sources, in order.
Asciidoctor drops comments before they reach the HTML, so this is the one check that reads the sources rather than the renderings.
The scan is a heuristic: without a block scanner it cannot tell a comment from a line of code inside a listing block.
Both sides are scanned the same way, so a misread line reports a difference only when formatting really changed it.

Verbatim content::
The content of every code and literal block, byte for byte.
Whitespace carries meaning there, which is what lets the rendering check ignore it everywhere else.

== The Asciidoctor cases

The case set is every test input of the Asciidoctor test suite, one file per case.
Those inputs sit inside the Ruby test files rather than in `.adoc` files, so link:../tools/fetch-asciidoctor-cases[`tools/fetch-asciidoctor-cases`] lifts them out.
The pinned tag tracks the Asciidoctor release the checks render with; regenerate the cases after changing it:

[source,shell]
----
go run ./tools/fetch-asciidoctor-cases
----

== Running

[source,shell]
----
go test ./...          # includes the Asciidoctor cases, about 25 seconds
go test -short ./...   # skips them
----

The run needs Asciidoctor on the `PATH`, and fails at once without it.

= Contributing

== Conventions

* English by default.
* https://www.conventionalcommits.org/[Conventional Commits], PR titles included.
* One logical change per commit, so history stays reviewable and revertable.
* Work on feature branches, never commit to the default branch.
* No emojis in commits, code, or comments.

== Code style

=== Shell

Shell scripts follow the https://google.github.io/styleguide/shellguide.html[Google Shell Style Guide] plus these project conventions:

* Shebang `#!/usr/bin/env bash`, so the script works wherever bash is installed.
* Strict mode `set -o errexit -o nounset -o pipefail` as the first statement.
* Longform flags (e.g. `--recursive` instead of `-r`).
* A comment at the top naming the supported platforms where they are not obvious.
* No GNU-only tool options in a script that also runs on macOS.

=== GoLang

* https://go.dev/doc/effective_go[Effective Go] and the https://google.github.io/styleguide/go[Google Go Style Guide], plus the rules in link:.golangci.yml[`.golangci.yml`].

=== Comments

* Comments explain the why, not the what.
* Prefer clear code over a comment, and one line over a paragraph; having no comment is often the correct state.
* Every fact has one canonical place, and a comment is either that place or a pointer to it.

== AI-assisted contributions

AI tools are welcome, but the author stays fully responsible for the result.

* Understand every line you submit; you must be able to explain it.
* All code must be human-readable, and simplified beyond a raw generated draft.
* Trim generated comments: models over-explain, so cut anything that restates the code or repeats context already stated nearby.
* Self-review the full diff before opening a PR for review.

== Documentation

* All documentation is AsciiDoc, except the Agent tooling requires Markdown (e.g. `AGENTS.md`).
* One sentence per line, so diffs stay readable.
* Prose follows the https://developers.google.com/style[Google developer documentation style guide].
